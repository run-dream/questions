### 🎯 **一、Progressive Disclosure（渐进式呈现）**

#### **问题：CLAUDE.md 膨胀**

传统的 CLAUDE.md 模式有一个严重问题——**膨胀**。当项目的规则、约定、规范全部塞进一个文件时：

| **问题** | **影响** |
|----------|---------|
| **Token 浪费** | 每条请求都加载全部内容 |
| **AI 选择性忽略** | 信息过多，AI 难以区分优先级 |
| **维护成本高** | 过时内容无人清理 |

#### **解决方案：Progressive Disclosure**

把详细规范移到独立文件中，CLAUDE.md 只保留链接（Context Pointers），让 AI **按需读取**。

```
传统方式：
  CLAUDE.md（包含所有规则） → 每次都全部加载 → 浪费 Token

Progressive Disclosure：
  CLAUDE.md（只放链接指针） → AI 需要时才读取具体文件 → 节省 Token
```

### 🧩 **二、Agent Skills 的工作机制**

Agent Skills 是 Progressive Disclosure 的进阶实现。

#### **Skill 的注册方式**

一个 Skill 包含三个部分：
- **Name**：技能名称（LLM 可见）
- **Description**：简短描述（LLM 可见）
- **Body/Content**：详细的规则和指令（按需读取）

#### **加载机制**

| **部分** | **默认加载** | **描述** |
|----------|-------------|---------|
| **Name** | 是 | Agent 在 `/skills` 命令中能看到所有 Skill 的名称 |
| **Description** | 是 | Agent 能看到的简短描述 |
| **Body** | 否 | 仅在 Agent 判断"这个 Skill 可能有用"时才会读取 |

> **关键特性**：Name + Description 默认可见但占用极少的 Token，Body 按需读取。这解决了 CLAUDE.md 膨胀的问题。

#### **注册命令**
```
/skills
→ 列出所有已注册的 Agent Skill
```

### 🔗 **三、Context Pointers（上下文指针）**

#### **定义**

Context Pointers 是从 CLAUDE.md 或 Skill Description 中指向具体参考文件的 **Markdown 链接**。

#### **工作机制**

- Agent 默认只看到指针（链接本身）
- 需要时才会去读取目标文件内容

#### **示例**

在 CLAUDE.md 中：
```markdown
- [API 设计规范](./docs/api-style-guide.md)
- [测试约定](./docs/testing-conventions.md)
- [组件库使用指南](./docs/component-guide.md)
```

**多重指针效应**：同一个 Skill 同时出现在 CLAUDE.md 和另一个 Skill 的 Description 中，被调用的概率会增加。

#### **Context Pointer 的演进**

| **阶段** | **特点** | **缺点** |
|----------|---------|----------|
| **CLAUDE.md 全部内容** | 一次性加载全部规则 | 膨胀后 Token 浪费 |
| **Progressive Disclosure** | CLAUDE.md 只放简要指针 | 仍需手动管理 |
| **Agent Skills** | Name+Description 默认可见 | 需要注册 Skill |
| **Context Pointers** | 链接放入 CLAUDE.md + Skill Description | 多重指针增加调用概率 |

### ⚠️ **四、/init 命令不推荐使用**

> 课程明确表示：**`/init` 命令不推荐使用**。

| **问题** | **说明** |
|----------|---------|
| **内容冗余** | 生成的内容大部分无用 |
| **容易过时** | 生成的规则随时间推移迅速过期 |
| **不精准** | 无法准确反映团队的真实编码约定 |

**推荐做法**：手动编写 CLAUDE.md 和 Skill 文件。
