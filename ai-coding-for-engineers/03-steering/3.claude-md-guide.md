### 📄 **一、CLAUDE.md 是什么？**

CLAUDE.md 是 Claude Code 的**项目级 Steering 文件**，位于项目根目录，每次新会话自动加载到上下文中。

| **属性** | **说明** |
|----------|---------|
| **位置** | 项目根目录 `CLAUDE.md` |
| **加载方式** | 每次新会话自动读入上下文 |
| **范围** | 当前项目，团队共享（Git 管理） |
| **维护方式** | 手动编写 |

---

### 🧠 **二、User Memory vs Project Memory**

#### **User Memory（`~/.claude/CLAUDE.md`）**

| **属性** | **说明** |
|----------|---------|
| **位置** | `~/.claude/CLAUDE.md` |
| **范围** | 全局，跨所有项目生效 |
| **维护方式** | 纯手动编辑 |
| **典型内容** | 编码习惯、语言偏好、个人工作流约定 |
| **优先级** | 低于 Project Memory（冲突时 Project Memory 覆盖） |

#### **Project Memory（项目 `CLAUDE.md`）**

| **属性** | **说明** |
|----------|---------|
| **位置** | 项目根目录 `CLAUDE.md` |
| **范围** | 当前项目，团队共享 |
| **维护方式** | 手动，Git 版本控制 |
| **典型内容** | 项目约定、编码风格、架构决策 |

### ✅ **三、CLAUDE.md 的最佳实践**

#### **适合放在 CLAUDE.md 的内容**

| **类别** | **示例** |
|----------|---------|
| **项目约定** | 命名规范、目录结构约定 |
| **编码风格** | TypeScript 风格、组件模式 |
| **技术栈决策** | 使用的框架、库版本 |
| **不会过时的信息** | 架构原则、设计模式偏好 |

#### **不适合放在 CLAUDE.md 的内容**

| **类别** | **原因** |
|----------|---------|
| **会过时的文件路径** | 重构后路径变化，CLAUDE.md 需要同步更新 |
| `package.json` 中的 scripts | 命令会变化，且 Agent 可以直接读取 `package.json` |
| **临时性 TODO** | 完成后不清理就是垃圾信息 |
| **每个文件的具体描述** | 过于细致，AI 可能选择性忽略 |

#### **核心原则**
> CLAUDE.md 中的每条信息都在消耗 Token。每增加一行，就是增加一次 AI "忽略"的风险。

---

### ⚠️ **四、CLAUDE.md 膨胀问题**

#### **为什么 CLAUDE.md 容易膨胀？**

| **原因** | **表现** |
|----------|---------|
| **群策群力（众包式）** | 团队每个成员都往里加自己关心的规则 |
| **只加不减** | 规则只追加，没人清理过时的 |
| **过于细致** | 试图覆盖所有边缘情况 |
| **一次性写入** | 用 `/init` 自动生成大量的默认规则 |

#### **膨胀的后果**

1. **Token 浪费** — 每次请求都加载 100+ 行规则
2. **AI 选择性忽略** — System prompt 明确说 "only if highly relevant"，信息过多时 AI 可能跳过
3. **维护成本高** — 无人清理过时内容，规则质量持续下降

### 🔧 **五、推荐的 CLAUDE.md 结构**

```markdown
# Project Name

## Tech Stack
- React 18 + TypeScript
- Next.js 14 (App Router)
- Tailwind CSS
- PostgreSQL + Prisma

## Project Conventions
- Components in `src/components/`
- Pages in `src/app/`
- API routes in `src/app/api/`
- Tests co-located with source files

## Key Decisions
- Server components by default, client components only when needed
- Error boundaries at route segment level
- No default exports (named exports only)

## Context Pointers
- [API Design Guide](./docs/api-guide.md)
- [Testing Conventions](./docs/testing.md)
- [Component Patterns](./docs/components.md)
```

### ❌ **六、/init 命令为什么不推荐使用？**

> **讲师的明确建议**：不要使用 `/init` 命令。

| **问题** | **说明** |
|----------|---------|
| 内容大部分无用 | `/init` 生成的规则覆盖范围广但深度不足 |
| 容易过时 | 自动生成的规则无法反映项目的真实演变 |
| 没有针对性 | 无法准确捕捉团队的独特约定和偏好 |

**推荐做法**：手动编写 CLAUDE.md，只包含对项目真正重要的信息。
