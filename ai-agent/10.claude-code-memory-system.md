以下是根据课程 "AI Coding for Real Engineers" (Cohort 004, Lessons 28-35) 中关于 Claude Code 三层记忆体系与 Steering 机制的系统性总结。

---

### 🧠 **一、Claude Code 的三层记忆架构**

使用 `/memory` 命令可以查看三层记忆的整体状态：

| **层级** | **文件位置** | **范围** | **维护方式** |
|----------|-------------|----------|-------------|
| **User Memory** | `~/.claude/CLAUDE.md` | 全局，所有项目 | 手动维护 |
| **Project Memory** | 项目根目录 `CLAUDE.md` | 当前项目 | 手动维护（团队共享） |
| **Auto Memory** | `.claude/memory/` | 当前项目 | Claude 自动生成 |

---

### 👤 **二、User Memory（`~/.claude/CLAUDE.md`）**

- **作用**：存储个人全局偏好，跨所有项目生效
- **典型内容**：编码习惯、语言偏好（如"总是用中文回复"）、个人工作流约定
- **维护方式**：纯手动编辑，不会自动变更
- **特点**：每次 Claude Code 启动都会读取，但读取优先级低于 Project Memory（若有冲突，Project Memory 覆盖 User Memory）

---

### 📄 **三、Project Memory（CLAUDE.md）**

项目级别的 Steering 文件，位于项目根目录。第 28-30 课详细讲解了其设计哲学与使用规范。

#### **核心特性**

- **自动加载**：每次新会话自动读入上下文
- **全局生效**：每条请求都在消耗 token
- **AI 选择性遵循**：System prompt 中明确说 "only if highly relevant"，AI 可能忽略某些内容
- **适合存放**：不会过时的项目约定、编码风格偏好
- **不适合存放**：会过时的具体文件路径、package.json 中的 scripts、临时性 TODO

#### **常见问题：CLAUDE.md 膨胀**

CLAUDE.md 容易膨胀成 100+ 行垃圾指令，导致：
- Token 浪费（每条请求都加载全部内容）
- AI 选择性忽略（信息过多，AI 难以区分优先级）
- 维护成本高（过时内容无人清理）

#### **解决方案（第 31-34 课）**

**Progressive Disclosure 模式**：把详细规范移到独立文件中，CLAUDE.md 只保留链接（Context Pointers）。

> ⚠️ **`/init` 命令不推荐使用** — 生成的内容大部分无用且容易过时。推荐手动编写 CLAUDE.md。

---

### 🤖 **四、Auto Memory（`.claude/memory/`）**

第 35 课介绍的新功能。Claude 在多次会话中自己观察到的项目模式，自动写进 `.claude/memory/` 目录。

#### **工作方式**
- 和 CLAUDE.md 一起读入上下文
- 由 Claude 自身在多次会话中积累
- 自动生成，无需手动干预

#### **讲师态度：谨慎（Cautious）**
- 功能较新，不确定是否真正有用
- 存在多个风险点：
  - **过时信息**：记录了已弃用的 API、已废弃的方案
  - **无用提示**：如记录 `v.mock is hoisted` 这类琐碎观察
  - **与手动引导冲突**：Auto Memory 的内容可能与 CLAUDE.md 中的手动指令矛盾
- **建议**：每几周检查一次 `.claude/memory/`，清理不需要的内容

### 🧭 **五、Steering 机制演进路线**

从传统 CLAUDE.md 到现代的多层引导系统：

```
CLAUDE.md（全局，每次请求都加载）
  → 改进：Progressive Disclosure（渐进式呈现），只放链接
    → Agent Skills（按需加载，name + description 默认可见，正文按需读取）
      → Context Pointers（Markdown 链接，形成文件系统式导航）
        → Auto Memory（Claude 自我引导，自动积累）
```

| **阶段** | **特点** | **缺点** |
|----------|---------|----------|
| **CLAUDE.md 全部内容** | 一次性加载全部规则 | 膨胀后 token 浪费，AI 选择性忽略 |
| **Progressive Disclosure** | CLAUDE.md 只放简要指针 | 仍需手动管理文件结构 |
| **Agent Skills** | name + description 默认可见，正文按需读取 | 需要注册 Skill |
| **Context Pointers** | CLAUDE.md + Skill description 中放链接 | 多指针增加被调用概率 |
| **Auto Memory** | Claude 自动积累观察 | 可能过时或无用，需定期审查 |

---

### 🔗 **六、Context Pointer（上下文指针）**

**定义**：从 CLAUDE.md 或 Skill description 中指向具体参考文件的 Markdown 链接。

**工作机制**：
- Agent 默认只看到指针（链接本身）
- 需要时才会去读取目标文件内容
- 多重指针效应：同一个 Skill 同时出现在 CLAUDE.md 和另一个 Skill 的 description 中，被调用的概率增加

**示例**：
```markdown
<!-- 在 CLAUDE.md 中 -->
- [API 设计规范](./docs/api-style-guide.md)
- [测试约定](./docs/testing-conventions.md)
```

### 📊 **八、记忆层对比总结**

| **维度** | **User Memory** | **Project Memory** | **Auto Memory** |
|----------|----------------|-------------------|----------------|
| **文件位置** | `~/.claude/CLAUDE.md` | 项目根 `CLAUDE.md` | `.claude/memory/` |
| **范围** | 全局，所有项目 | 当前项目，团队共享 | 当前项目 |
| **维护方式** | 手动 | 手动 | 自动（Claude 自生成） |
| **适合内容** | 个人编码习惯、语言偏好 | 项目约定、编码风格 | 项目模式洞察 |
| **风险** | 与项目冲突 | 膨胀后 token 浪费 | 过时信息、无用提示 |
| **审查频率** | 偶尔 | 定期 | 每几周 |
